# Signal 40 UI 宽度与导航一致性 Review

> Review 方式：第一轮静态审查 + 整改后组件/浏览器回归
> 状态：共享实现已落地；375px 与 1440px 定向回归通过

## 1. 总体结论

八个主要页面目前使用五种主内容宽度，且全站一级导航只完整出现在雷达页。其他页面各自拼装“返回雷达”和少量邻接入口，没有单一导航配置、稳定 active 状态或统一移动端折叠策略。项目工作台的生产阶段导航是合理的二级上下文导航，但缺少统一的全站一级导航承载。

建议确立三种受控规格：

| Token | 建议值 | 页面类型 |
| --- | --- | --- |
| `standard` | `max-w-6xl` | 自动化、待办、运营、系统自检和普通配置 |
| `wide` | `max-w-7xl` | 雷达、来源、治理等高信息密度页面 |
| `workspace` | `max-w-[1500px]` | 项目工作台等三栏生产界面 |

具体值可以由设计最终冻结，但同一 token 必须同时驱动页头和正文，业务页面不得继续新增任意 `max-w-*`。

## 4. 统一导航信息架构

一级导航建议固定为：雷达、来源、自动化、待办、运营、治理；系统自检放入统一“系统”入口。所有页面读取同一份配置，避免页面自行维护入口顺序和名称。

项目工作台采用两层结构：共享一级导航负责跨产品区域移动；面包屑或父级链接表达“雷达 / 项目”；现有生产阶段 nav 只表达项目内部阶段。状态筛选、刷新、创建等属于 `PageHeader.actions`，不应混入全站导航。

统一组件至少需要表达：

- 当前页面 `aria-current="page"`、可见 focus、键盘顺序和一致的图标/标签。
- 移动端折叠按钮、打开/关闭、Escape、焦点锁定与关闭后焦点回收。
- 权限入口的单一策略：统一隐藏，或统一禁用并解释。
- 深链接、刷新和浏览器前进/后退后 active 状态保持正确。

## 5. 响应式验收矩阵

整改完成后，对八页逐一执行以下视口：320、375、768、1024、1280、1440、1920。每个视口保存截图并记录：

1. 页头与正文左右边界是否一致。
2. 是否存在非预期横向滚动。
3. 表格/图表是否使用局部滚动或卡片降级。
4. 导航是否可达、当前态是否明确。
5. 触控目标、文本截断和动作区是否互相覆盖。
6. 键盘焦点是否可见且顺序合理。

当前静态证据足以确认结构不统一，但不足以把窄屏溢出或键盘行为判为已验收；这些项目保持 `Not run`，不得用源码推断为通过。

## 6. 2026-09-10 整改后结果

- `components/page-shell.tsx` 提供共享 `PageHeader`、`PageContainer`、桌面导航和移动 Sheet；`lib/page-shell.ts` 是唯一导航与宽度 token 权威来源。
- 雷达、来源、治理统一为 `wide`；自动化、待办、运营、系统自检统一为 `standard`；项目工作台使用 `workspace`，并保留独立的生产阶段二级导航和“雷达 / 项目工作台”层级提示。
- `test/page-shell.test.ts` 固定导航顺序、父级 active 规则和三种主宽度 token。
- 1440px 浏览器回归：七个一级页面均无横向溢出，页头与正文 token 一致，完整导航与 `aria-current` 正确。
- 375px 浏览器回归：七个一级页面均无横向溢出；桌面导航隐藏、统一菜单按钮可见；Sheet 打开成功并把焦点移入导航。
- 项目工作台当前测试数据库没有可访问项目，因此本轮以共享组件测试、静态结构检查、TypeScript 与生产构建作为证据；320/768/1024/1280/1920 的截图基线仍可在视觉回归平台补齐，但不再是共享实现缺陷。
