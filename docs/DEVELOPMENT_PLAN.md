## 1. 结论与建设原则

Signal 40 的最终形态不是“选题榜 + `project.json` 导出器”，而是一套可持续运行、可审计、可恢复的视频生产系统：

```text
授权来源采集
  → 归一化、去重、聚类与评分
  → 原始资料检索与声明级证据绑定
  → 编辑选题与事实核验
  → 脚本、分镜和视觉方案生成
  → 资产、配音、字幕与音乐生产
  → Remotion 渲染与自动质检
  → 人工终审、排期与发布
  → 表现数据回流、评分校准与复盘
```

所有阶段都必须遵守五条原则：

1. **事实先于生成**：模型可以组织表达，不能替代信源；每个可核验声明必须能回到证据。
2. **人工掌握发布权**：默认不自动发布，生产批准与发布批准是两个独立动作。
3. **版本不可漂移**：批准后的证据、脚本、资产和渲染配置形成不可变快照。
4. **任务可重试但不重复生效**：所有长任务都使用幂等键、重试和死信处理。
5. **控制面与渲染面分离**：Node 控制面负责工作台和治理；Chromium、FFmpeg、Remotion 在独立媒体执行环境运行。

当前代码已按本文推进到 P0–P6 的本地全链路候选。完整产品是否可发布仍必须按第 16 节验收，不能用本地构建、模拟回归或单条成片替代真实供应商、渠道、staging 和责任人签字。

## 2. 产品目标

### 2.1 业务目标

- 每天稳定发现 10–30 个候选题，产出 3–10 个经过核验的可制作选题。
- 将“发现信号到首版成片”的人工周转时间控制在 30–90 分钟。
- 所有关键数字、因果判断和结论都能定位到原始资料或明确标记为分析观点。
- 支持 30–90 秒竖屏视频，后续可扩展横屏和多语言版本。
- 支持多模板、多账号、多渠道，但先以一个团队、一个品牌完成稳定闭环。

### 2.2 不以自动化为代价的边界

- 不抓取未授权内容，不绕过登录、付费墙、验证码或平台风控。
- 不把转述文章当成原始事实来源。
- 不让模型自行补齐缺失数字、日期、单位、币种或比较基准。
- 不在未解决证据冲突、版权不明、合规风险未处理时进入渲染或发布。
- 不把播放量优化凌驾于准确性、风险控制和品牌可信度之上。

## 3. 使用者与权限

| 角色 | 核心职责 | 关键权限 |
| --- | --- | --- |
| 研究员 | 配置来源、补充资料、绑定证据 | 编辑文章、声明和证据，不可发布 |
| 编辑 | 选题、脚本、分镜、事实核验 | 批准证据与脚本，不可修改系统配置 |
| 制作人 | 资产、声音、模板、渲染和质检 | 发起渲染、批准成片 |
| 发布者 | 渠道文案、排期、发布和撤回 | 独立发布批准 |
| 管理员 | 成员、密钥、供应商、保留策略 | 配置权限，不参与内容事实判断 |
| 审计者 | 查看历史版本、证据和操作轨迹 | 只读 |

小团队可以一人兼任多个角色，但系统仍保留“内容批准”和“发布批准”两个独立事件；高风险选题可配置为双人复核。

## 4. 端到端工作流

### 4.1 阶段与产物

| 阶段 | 输入 | 系统产物 | 完成条件 |
| --- | --- | --- | --- |
| 采集 | 来源配置、关键词、时间窗 | `IngestionRun`、原始记录、采集错误 | 来源授权有效，运行有审计记录 |
| 归一化 | 原始记录 | 标准化 `ArticleRevision` | URL、时间、来源类型和哈希合法 |
| 选题发现 | 标准化文章 | `TopicCandidate`、评分拆解 | 聚类可解释，来源关系可追溯 |
| 深度研究 | 候选题 | `Claim`、`EvidenceLink`、冲突项 | 每个关键声明都有支持或反驳证据 |
| 选题批准 | 研究包 | 不可变 `ResearchSnapshot` | 自动门禁与人工核验均通过 |
| 脚本 | 研究快照、品牌规范 | 脚本版本、读音标注、风险提示 | 声明覆盖率 100%，时长预算可行 |
| 分镜 | 已批准脚本 | 时间轴、图表规范、镜头清单 | 每句旁白与画面、来源对应 |
| 资产生产 | 分镜 | 图表、图片、视频、字体、音乐记录 | 版权、尺寸、色彩和来源完整 |
| 声音生产 | 脚本 | TTS/真人音轨、字幕、时间戳 | 发音、数字、停顿、响度通过 |
| 渲染 | 完整项目快照 | 预览片、正式片、封面、校验报告 | 可重复渲染，输出哈希固定 |
| 质检 | 正式片与全部证据 | 自动 QC、人工 QC、修改单 | 内容、视觉、音频、技术检查通过 |
| 发布 | 已终审版本 | 渠道任务、平台内容 ID、发布时间 | 发布者明确批准，幂等提交成功 |
| 回流 | 平台指标 | 指标快照、复盘、模型校准数据 | 指标口径、归因窗口和版本明确 |

### 4.2 内容项目状态机

```text
DRAFT
  → RESEARCHING
  → EVIDENCE_READY
  → EDITOR_APPROVED
  → SCRIPT_DRAFT
  → SCRIPT_APPROVED
  → ASSETS_READY
  → RENDER_QUEUED
  → RENDERING
  → QC_PENDING
  → QC_APPROVED
  → PUBLISH_SCHEDULED
  → PUBLISHED
  → MEASURED

任意阶段可进入：CHANGES_REQUESTED / REJECTED / FAILED / CANCELLED
```

状态只能通过领域命令迁移，不能由页面任意覆盖。每次迁移记录操作者、原因、前后版本、时间和关联作业。

## 5. 系统架构

### 5.1 控制平面

部署在 Sites/Cloudflare Workers，负责：

- 工作台、搜索、审核和权限；
- HTTP API、Webhook 接收和任务编排；
- D1 元数据与状态；
- R2 资产索引及短时授权地址；
- Queue 任务投递、重试状态和审计；
- WebMCP 工具，让 Agent 在相同权限和门禁下完成操作。

### 5.2 媒体执行平面

独立的容器化 Render Worker 负责：

- Remotion bundle、帧渲染和 MP4 编码；
- Chromium、FFmpeg、字体和媒体探测；
- 波形、响度、黑帧、静音、字幕安全区检查；
- 通过短时签名 URL 获取输入并上传输出；
- 以渲染快照哈希作为幂等键。

不在 Workers 内执行视频渲染。Workers 的 128 MB 隔离环境适合控制请求，不适合 Chromium/FFmpeg 媒体任务。

### 5.3 数据与消息流

```text
RSS / Public JSON / 公开网页或 Feed / CSV / 手工输入
                │
                ▼
       Sites API + D1 metadata
                │
        ┌───────┴────────┐
        ▼                ▼
   R2 raw/assets     Queue jobs
                         │ at-least-once
                         ▼
                Render Worker pool
                         │
                         ▼
                 R2 output + QC
                         │
                         ▼
                 Sites review/publish
```

Queue 按至少一次投递设计，消费端必须幂等；超过重试次数进入 DLQ，由工作台显示、重放或关闭。

## 6. 领域模型

### 6.1 采集与研究

- `SourceConfig`：来源、适配器、授权方式、速率、保留规则、启停状态。
- `IngestionRun`：触发方式、时间窗、游标、计数、失败原因和成本。
- `Article`：规范 URL、来源、当前版本、首次/最近发现时间。
- `ArticleRevision`：内容哈希、标题、摘要、作者、发布时间、原始载荷位置、抓取时间。
- `TopicCandidate`：聚类版本、热度、评分、评分特征和证据门禁。
- `Claim`：结构化声明、类型、数值、单位、币种、统计周期、主体和不确定性。
- `EvidenceLink`：声明与文章版本之间的支持、反驳或背景关系，以及页码、段落、表格或时间码定位。
- `ResearchSnapshot`：批准时冻结的候选、声明、证据和冲突集合。

### 6.2 内容生产

- `ContentProject`：主题、目标渠道、语言、目标时长、状态、负责人。
- `ScriptVersion`：旁白、屏幕文字、免责声明、模型/提示词版本、人工修改。
- `StoryboardVersion`：场景顺序、时长预算、转场和视觉意图。
- `ChartSpec`：数据点、单位、来源、比例尺、突出项和可视化类型。
- `Asset`：对象路径、媒体类型、哈希、版权依据、生成/获取来源、保留期。
- `VoiceTrack`：供应商、声音、语速、读音词典、音频哈希和时间戳。
- `CaptionTrack`：逐词/逐句时间、样式、安全区和人工修改。
- `RenderSnapshot`：所有输入版本与模板版本的不可变组合。
- `RenderJob`：状态、尝试次数、执行节点、日志位置、输出和耗时。
- `QCReport`：规则结果、抽帧、探测信息、人工意见和批准事件。
- `PublishJob`：渠道、账号、文案、定时、幂等键、平台内容 ID。
- `MetricSnapshot`：渠道指标、抓取时间、归因窗口和数据口径。
- `AuditEvent`：操作者、动作、对象、前后摘要、会话信息和时间。

### 6.3 存储分工

- D1：结构化元数据、版本关系、状态、审批、幂等键和审计索引。
- R2：原始载荷、图像、音频、字幕、字体包、预览片、成片、封面和日志归档。
- Queue：采集、研究、TTS、渲染、质检、发布、指标回流任务。
- 可选分析仓库：长期指标、A/B 数据和跨渠道聚合；不阻塞首个完整生产版本。

## 7. 协议演进

当前 `project.json` 1.0 只包含主题、一个声明、来源、四个场景和基础渲染参数。完整生产协议升级为 2.0：

```text
VideoProject 2.0
├── identity         项目、版本、语言、渠道、负责人
├── research         不可变研究快照与声明覆盖
├── script           旁白、屏幕文字、免责声明、读音
├── timeline         场景、镜头、转场、帧预算
├── visuals          ChartSpec、颜色、单位、来源脚注
├── assets           对象引用、哈希、版权和裁切策略
├── audio            语音、音乐、响度、混音与时间戳
├── captions         字幕片段、安全区和样式
├── render           编码、尺寸、帧率、质量、模板版本
├── distribution     渠道标题、描述、标签、封面和排期
└── provenance       生成器、模型、提示词、操作者和时间
```

要求：

- 提供 1.0 → 2.0 迁移器，旧导出文件仍可打开。
- JSON Schema、TypeScript 类型和数据库版本共同演进。
- 未知字段拒绝或进入兼容层，禁止静默丢失。
- 所有对象引用携带内容哈希，渲染前再次验证。

## 8. 各生产环节设计

### 8.1 来源采集

- 适配器统一实现 `discover/checkpoint/fetch/normalize/health`。
- 支持 RSS、Public JSON、公开网页/热榜、公众号与小红书 OpenCLI 候选搜索或第三方 RSS、公司公告、交易所/市场数据和手工导入。
- 保存游标、速率限制、重试原因和字段质量；来源失效不能静默返回空成功。
- 原文内容是否保存由授权和保留规则决定；默认只保留必要元数据、哈希和定位信息。
- 定时任务与手工运行共用相同管道，所有任务可回放。

### 8.2 聚类、评分与选题

- 先做确定性规范化和去重，再做实体、事件、时间窗口和主题聚类。
- 评分保留可解释特征：共振、速度、数字冲击、来源质量、时效、可视频化、竞争密度和风险。
- 阈值只用于排序，不等于事实正确或允许发布。
- 保存算法版本和输入快照；新算法通过离线回放比较，不覆盖历史结果。
- 为合并错误、拆分错误和错过热点建立人工标注集。

### 8.3 声明级研究与核验

- 从候选题抽取原子声明，至少分为事实、数字、比较、因果、预测、观点六类。
- 数字声明必须包含数值、单位、币种、时间范围、同比/环比基准和主体。
- 每个声明绑定支持和反驳证据；冲突项必须显式解决或从脚本删除。
- 原始来源优先级高于媒体转述；模型输出不能作为证据。
- 审批时冻结 `ResearchSnapshot`，后续来源变化会触发“证据过期”而不是静默修改。

### 8.4 脚本与分镜

- 脚本生成使用结构化输出，每句旁白关联一个或多个 `claim_id`。
- 区分事实陈述、分析推断和风险提示；推断必须用相应措辞表达不确定性。
- 时长以实际 TTS 对齐结果为准，不按字数硬猜；超长自动给出删改建议，不直接截断。
- 分镜为每段定义旁白、屏幕文字、图表、来源脚注、镜头运动和帧区间。
- 编辑器支持版本比较、逐句退回、锁定已批准段落和评论。

### 8.5 数据视觉与资产

- 图表只从结构化数据生成，保存原始值、变换公式、单位和来源。
- 禁止截断坐标轴或通过面积、颜色、动画夸大变化；特殊比例尺必须提示。
- 所有图片、视频、字体、音乐和品牌素材记录版权依据和使用范围。
- AI 生成资产明确记录模型、提示词和生成时间，不用于伪造新闻现场或公司文件。
- 资产上传直达 R2，使用短时、对象级授权，不把长期凭据放入浏览器。

### 8.6 配音、字幕与音乐

- TTS 供应商通过接口适配，支持替换、降级和成本追踪。
- 保存中文数字、英文缩写、公司名和单位的读音词典。
- TTS 返回音频后做强制对齐，生成逐句和逐词时间戳。
- 字幕在竖屏安全区内自动换行，限制单行长度、行数和最短显示时间。
- 音乐必须有授权；人声优先，响度目标和峰值按渠道预设配置。

### 8.7 Remotion 渲染

- React 组件只消费冻结的 `RenderSnapshot`，渲染期间不访问会变化的业务 API。
- 模板、字体、图表、转场和编码预设都有版本号。
- 先生成低码率预览，再由终审版本生成正式 MP4、封面和缩略图。
- 作业支持取消、超时、重试、优先级、并发配额和成本预算。
- 同一输入哈希与渲染预设只能产生一个逻辑结果；重复消息返回已有作业。

### 8.8 自动与人工质检

自动检查包括：

- Schema、声明覆盖、证据状态、资产哈希和版权字段；
- 场景重叠/空洞、总帧数、字幕越界、文字安全区和字体缺失；
- 分辨率、帧率、编码、码率、时长、音频峰值、静音和黑帧；
- 来源脚注可读性、数字与脚本一致性、禁止词和免责声明；
- 抽帧视觉回归和关键场景截图。

人工终审包括：

- 事实与口径；
- 叙事是否误导；
- 图表和画面是否支持旁白；
- 发音、字幕、节奏、品牌和渠道规范；
- 最终发布文案、封面和账号。

### 8.9 发布与效果回流

- 每个平台使用独立适配器，默认生成“待发布包”，由发布者确认后执行。
- 保存标题、描述、标签、封面、计划时间、平台返回 ID 和最终 URL。
- 使用 `project_version + channel + account + schedule` 生成幂等键，防止重复发布。
- 支持失败重试、取消排期、下架/更正流程和发布后勘误记录。
- 回流播放、完播、3 秒留存、互动、关注转化和负面反馈；保留抓取时间与口径。
- 评分校准使用延迟标签和离线评估，禁止直接用单条爆款更新线上权重。

## 9. 强制门禁

| 门禁 | 检查内容 | 失败后动作 |
| --- | --- | --- |
| G0 来源与授权 | 来源授权、访问方式、保留规则 | 拒绝采集或只保留元数据 |
| G1 输入质量 | URL、时间、字段、重复、异常量 | 隔离坏记录，运行标记部分失败 |
| G2 自动证据 | 原始来源、独立来源、冲突和时效 | 不能进入编辑批准 |
| G3 人工研究 | 声明、数字、口径、风险备注 | 退回研究或驳回选题 |
| G4 脚本覆盖 | 每句事实对应已批准声明 | 不能生成正式分镜 |
| G5 资产权利 | 图片、字体、音乐、生成资产记录 | 不能进入正式渲染 |
| G6 技术与内容 QC | 视频、音频、字幕、事实、品牌 | 退回对应生产阶段 |
| G7 发布批准 | 成片哈希、渠道、账号、时间 | 不能调用平台发布接口 |
| G8 发布后治理 | 指标异常、投诉、事实更新 | 告警、暂停分发、勘误或下架 |

G3、G6、G7 是独立审批事件，不能由任务成功状态替代。

## 10. API 与并发控制

核心 API 按 `/api/v1` 版本化：

- `/ingestion-runs`：创建、查看、重试采集运行。
- `/topics`：候选列表、聚类调整、研究包。
- `/claims` 与 `/evidence-links`：声明和证据关系。
- `/projects`：创建内容项目并读取状态。
- `/script-versions`、`/storyboard-versions`：版本化编辑。
- `/assets/uploads`：生成对象级上传授权并完成校验。
- `/voice-jobs`、`/render-jobs`、`/qc-reports`：长任务控制。
- `/approvals`：证据、脚本、成片和发布批准。
- `/publish-jobs`、`/metric-snapshots`：发布与回流。

写操作要求：

- 客户端提供 `Idempotency-Key`；
- 可编辑对象使用版本号或 ETag，冲突返回 409；
- 审批命令携带被批准版本的哈希；
- Webhook 使用签名、时间窗和重放保护；
- API 错误区分校验、冲突、依赖失败、重试中和永久失败。

## 11. 安全、隐私、版权与领域合规

- 私有工作台默认最小权限；敏感管理操作启用强认证和短会话。
- 密钥只进入托管 Secret，不写入 D1、日志、浏览器或项目文件。
- R2 对象默认私有，下载/上传使用最小权限的短时 URL，并避免在日志中记录完整查询串。
- 原始资料、提示词、模型输出和渲染日志分别设置保留期；删除流程覆盖 D1 索引和 R2 对象。
- 对外视频显示来源、数据时间、必要免责声明和更正入口。
- 不提供个性化投资建议；观点与事实分离，收益、预测和风险表达需专项规则。
- 版权状态不明的素材只能作为内部研究参考，不能进入成片。
- 所有发布、撤回、勘误、权限和密钥配置行为进入不可变审计流。

## 12. 可观测性与服务目标

### 12.1 关键指标

- 采集成功率、字段完整率、重复率、来源延迟；
- 聚类合并/拆分错误率、候选采纳率、证据补全耗时；
- 声明覆盖率、事实退回率、脚本修改轮次；
- TTS、资产、渲染和发布的成功率、重试率、P50/P95 耗时与成本；
- QC 缺陷类别、发布后勘误率、重复发布数；
- 视频完播、留存、互动和转化，并按版本、渠道、主题分层。

### 12.2 初始 SLO

- 未核验声明进入发布：0。
- 重复逻辑发布：0。
- 关键操作审计覆盖率：100%。
- 控制面月可用性：≥99.9%。
- 渲染作业 30 分钟内完成率：≥98%。
- 渲染和发布失败在 5 分钟内可见，永久失败进入 DLQ。
- 发布后重大事实错误率：目标 0，任何一例都触发流程复盘。

阈值在真实运行 4 周后重新校准，但硬门禁不能因效率目标下调。

## 13. 测试与评估体系

### 13.1 自动化测试

- 单元：规范化、聚类、评分、状态机、时间轴和数据变换。
- 属性测试：重复输入、乱序消息、边界长度、非法 URL、时间和数值。
- 合约：Schema、API、适配器、Webhook、TTS 和发布供应商。
- 数据库：空库迁移、升级、回滚演练、并发冲突、幂等和索引计划。
- 集成：D1/R2/Queue/Render Worker 的完整任务链。
- 媒体：固定输入的帧级快照、音频探测、字幕边界和输出哈希。
- 浏览器：研究、审批、脚本、预览、终审和发布的关键路径。
- 安全：权限越权、签名重放、恶意媒体、公式/脚本注入和日志泄露。

### 13.2 内容评估集

- 至少 100 个历史财经事件，覆盖财报、商品、宏观、公司公告和市场传闻。
- 为每个事件标注正确聚类、关键声明、权威证据、冲突和可接受表达。
- 算法或模型升级必须比较召回、误合并、事实一致性和人工修改量。
- 生成质量采用盲评，模型评分只能作为辅助信号。

## 14. 部署与运行模型

环境分为：

- `local`：开发者 D1/R2 模拟、Remotion 本地渲染。
- `staging`：独立数据库、桶、队列、测试账号和供应商沙箱。
- `production`：私有控制面、生产队列、生产渲染池和渠道账号。

发布顺序：

1. 在目标提交 SHA 执行测试、构建、依赖与迁移检查。
2. 先应用向后兼容迁移，再发布控制面。
3. 发布 Render Worker 和模板版本，执行一条金丝雀渲染。
4. 用测试账号验证发布包或平台沙箱。
5. 开启生产流量并观察错误、队列积压和成本。
6. 保留上一版本模板和 Worker；数据库使用前向修复，不改写已应用迁移。

备份与恢复：D1 定期导出/时间点恢复演练；R2 开启生命周期和对象清单；每季度验证从研究快照重新生成成片。

## 15. 建设阶段与交付顺序

以下不是“做一个 MVP 再结束”，而是完整产品的连续交付顺序。每一阶段都必须交付生产可用的子系统和迁移路径。

### P0：基础治理与协议（1–2 周）

- 确定角色、状态机、版本、幂等、审计和错误分类。
- 将 `project.json` 升级为 2.0，并提供 1.0 兼容器。
- 引入 R2、Queue、项目/作业表和环境配置。
- 建立 staging、CI 门禁和发布清单。

### P1：来源与声明级研究（2–3 周）

- 来源配置、定时采集、检查点、重试和健康监控。
- RSS/HTTP/Web/CSV 适配器统一化。
- Claim、EvidenceLink、冲突和 ResearchSnapshot。
- 研究工作台、多人并发控制和审批。

### P2：脚本与分镜编辑（2–3 周）

- 结构化脚本生成、逐句证据覆盖和版本比较。
- 目标时长、读音、屏幕文字、免责声明和评论。
- 分镜时间轴、ChartSpec 和模板选择。
- 脚本批准门禁。

### P3：资产、配音、字幕与渲染（3–4 周）

- R2 上传、资产版权、裁切和派生版本。
- TTS 适配、读音词典、时间对齐、字幕和混音。
- Remotion 模板系统、Player 预览、Render Worker、Queue 与 DLQ。
- 预览片、正式片、封面和可重复渲染。

### P4：质检与发布（2–3 周）

- 自动媒体 QC、抽帧、视觉回归和人工终审页面。
- 渠道预设、发布包、独立发布批准和排期。
- 至少一个目标平台适配器，其余平台先交付可下载发布包。
- 更正、下架、失败恢复和审计闭环。

### P5：指标回流与运营（2 周）

- 指标采集、版本归因、主题/模板/渠道分析。
- 评分离线校准、A/B 实验与人工复盘。
- SLO 仪表板、成本预算、容量预警和运行手册。

### P6：规模化与灾备（持续）

- 多品牌、多语言、多团队和细粒度权限。
- 渲染池自动扩缩、优先级和成本路由。
- 备份恢复、供应商切换和季度故障演练。

计划假设：3 名工程人员、1 名设计/动效人员和兼职领域编辑可在约 12–16 周完成 P0–P5；单人实施应按 20–28 周规划。真实周期取决于发布平台 API、TTS 选择、素材版权流程和视觉模板数量。

## 16. 完整产品验收标准

只有以下全部通过，才能称为“全流程可用”，而不是 MVP：

1. 三类以上授权来源可定时采集，失败可见、可重试、可回放。
2. 候选题能完成声明级证据绑定、冲突处理、研究快照和人工批准。
3. 脚本每条事实都有证据覆盖，版本差异、评论和批准可审计。
4. 分镜、图表、资产、配音和字幕可在工作台完成并保存版本。
5. 从批准的 `RenderSnapshot` 能异步生成预览片和正式 MP4。
6. 自动 QC 能阻止时长、字幕、音频、黑帧、版权和事实覆盖问题。
7. 人工终审后才能创建发布任务；重复请求不会重复发布。
8. 至少一个真实渠道完成 staging/测试账号验收，并能处理失败、更正和下架。
9. 发布指标能回到具体项目、脚本、模板和选题算法版本。
10. 权限、密钥、审计、备份恢复、DLQ 和供应商降级演练通过。
11. 目标提交的测试、构建、迁移、依赖、浏览器和真实供应商验收全部留有证据。
12. 运行团队拥有告警、值班、故障处理和内容勘误手册。

## 19. 技术依据

- [Remotion](https://www.remotion.dev/) 支持用 React 生成 MP4，并提供服务端和批量渲染能力；商业使用前需按团队和自动化场景确认许可证。
- [Cloudflare Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)规定每个 isolate 的内存上限为 128 MB，因此这里只承担控制面工作。
- [Cloudflare Queues](https://developers.cloudflare.com/queues/reference/delivery-guarantees/)默认至少投递一次，作业必须通过唯一 ID 和幂等键去重，并配置[死信队列](https://developers.cloudflare.com/queues/configuration/dead-letter-queues/)。
- [Cloudflare R2](https://developers.cloudflare.com/r2/objects/upload-objects/)适合保存视频等大对象；大文件采用可恢复的分片上传，短时[签名 URL](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)按 bearer token 管理。
- 公众号和小红书可用 OpenCLI 做候选搜索，或接入经权利确认的第三方 RSS/Atom Feed；系统不托管登录状态，也不绕过平台访问限制。OpenCLI 未提供作者时发布主体保持 unknown。
